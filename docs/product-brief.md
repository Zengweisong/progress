## 已确认的需求

- Windows 应用，并支持 Android、iOS、网页。
- 参考 Notion 看板数据库，用于记录多个项目的进展。
- 同时作为个人知识库，项目和知识能够相互关联。
- 本地保存、离线可用、数据自己掌握。
- 操作简洁，打开即可记录、更新进展。

- 软件提供账号和云同步，登录即可使用；用户不需要自己部署服务器。

## 产品定位与关键体验

以项目为入口的个人工作台：管理正在做的事情，并把过程中的资料、笔记和复盘积累成可以复用的知识。

例如：在 Windows 新建“开发个人网站”项目；手机上记录一个想法并关联该项目；回到电脑后，在项目页面继续编辑这条笔记；项目结束后，笔记仍可在知识库中找到，并关联到下一个项目。

设计假设：首版服务个人使用；同步默认指同一人的设备同步。多人协作另行规划。用户已确认此首版范围；具体工程设计和视觉细节由原型验证后细化。

## 建议的首版范围

| 模块 | 首版行为 |
| --- | --- |
| 项目总览 | 项目看板、表格两种视图；按状态或单选属性分组；拖动卡片改变分组值 |
| 数据库属性 | 预置项目、任务、笔记三个集合；支持添加文本、数字、日期、单选、多选、复选框、网址属性 |
| 视图设置 | 保存筛选、排序、分组及卡片属性显示配置；不同视图使用同一份记录 |
| 项目详情 | 项目说明、任务看板、进展日志、关联笔记、附件 |
| 任务 | 标题、状态、优先级、截止日期、所属项目、详细内容；可直接从项目页面创建 |
| 项目进度 | 默认按已完成任务数 / 有效任务总数计算；无任务显示“暂无任务”；项目状态单独设置 |
| 笔记 | 标题、正文、标签、分类；支持标题层级、列表、待办、引用、代码块、链接和图片 |
| 知识关联 | 笔记可以独立存在，也可以关联多个项目；项目和笔记两侧都能查看关联 |
| 搜索 | 搜索本地已有的项目、任务、笔记标题和正文；附件正文索引留到后续 |
| 数据掌握 | 完整导出、备份及恢复；同步不替代备份 |
| 多端同步 | 离线编辑先保存至设备，联网后自动传输修改；提供同步状态和手动重试 |

首版不扩展任意数据库创建、公式语言、通用关系汇总、复杂嵌套页面、团队权限、实时多人编辑、AI 问答、知识图谱和插件系统。后续按实际使用情况增加。

## 界面结构

Windows 和宽屏网页：左侧导航（项目、知识库、收集箱、搜索），中间为看板或列表，打开记录后进入详情；提供快速新建和键盘操作。

Android 和 iOS：底部导航（项目、知识、收集箱），突出快速记录、查看任务和更改状态；看板提供横向浏览，同时提供便于单手使用的列表切换。核心数据编辑能力与桌面一致。

收集箱中的笔记无需先选分类或项目，之后再整理。基础使用无需先配置数据库。

## 本地与同步的行为约定

1. 本地创建、修改、搜索与拖动状态不等待网络响应；未登录也可以本地使用。首次启用同步时，明确将哪个本地工作区加入账号。
2. 同步不仅覆盖正文，还包括属性定义、记录、关系、视图设置、删除记录以及附件清单。
3. 客户端使用稳定记录 ID 和可重试的修改队列；同一修改重复发送不应产生重复笔记。
4. 首版采用保守冲突处理：不同记录可分别同步；同一记录发生并发修改时，保留共同基线与两个修改版本，提示用户合并或选择，不能静默丢弃其中一份。
5. 删除与离线编辑冲突时，将编辑版本保留在恢复区。同步删除与彻底清理分开，避免另一台离线设备使记录意外复活或内容丢失。
6. 附件单独显示上传、下载、失败状态；手机和网页可按需下载。离线只能打开已经下载的附件，不能把元数据同步成功显示成附件已可用。
7. 网页首次使用需要联网加载；离线能力依赖浏览器支持及已缓存的数据。浏览器本地数据可能被清理，产品需给出可理解的状态与恢复入口。
8. 账号退出前检查未同步修改，允许先同步或导出；不直接清空未保存的数据。
9. “数据自己掌握”至少包含本地可用及完整导出。云端是否采用端到端加密尚待决定，不能宣称云服务无法读取内容。

建议完整备份包包含结构化记录、属性、关系、视图、附件及版本格式；另提供便于外部阅读的 Markdown 正文和 CSV 表格导出。恢复首先导入为独立工作区，避免覆盖现有数据。

## 可选实现路线

以下为相对工作量比较，不是工期承诺。需求讨论开始时目录为空；当前已建立原生 HTML/CSS/JavaScript 交互原型。

| 路线 | 内容 | 相对工作量 / 风险 | 优点 | 代价 |
| --- | --- | --- | --- | --- |
| A：先交付网页和 Windows，再补移动 App | 首轮以 Windows 与响应式网页验证流程，手机临时使用网页；最终补齐 Android、iOS App | 中 / 中 | 最快获得可用反馈，可逐步复用界面与逻辑 | 初次交付不包含用户要求的两个手机 App |
| B：共享核心，交付四端（建议） | 从首版定义统一记录格式和同步协议；共享业务逻辑，适配桌面、手机和浏览器的存储与交互 | 大 / 中高 | 四端目标明确，功能与数据语义一致，适合持续维护 | 需要处理三个运行环境的离线存储、构建和发布 |
| C：四端独立实现 | Windows、Android、iOS、网页分别实现应用，共用服务端协议 | 很大 / 高 | 各端可以深度适配平台 | 重复开发多，编辑器和同步行为容易产生差异 |

用户已确认建议路线 B。正式工程通过小范围纵向验证降低风险：同一条笔记在四端离线保存、同步、产生冲突并恢复成功，再扩展完整看板与编辑器。当前先制作桌面 / 手机界面原型；客户端开发框架和同步服务技术尚未锁定，不将跨端复用等同于零适配成本。

## 同步服务方式（已确认）

- **已选择：应用提供账号和云同步**。用户登录即可使用，四端接入统一服务；需要长期运行服务、承担存储成本并管理账号。
- 曾考虑用户自建同步服务：用户需要部署和维护服务，不符合本次选择，首版不提供。
- 曾考虑连接用户 WebDAV / 网盘：另需验证服务商接口、浏览器跨域、凭证保护与并发行为，首版不提供。

本地工作区、完整导出与备份恢复保留在已选路线中。服务提供方的部署、维护和运行费用需在工程阶段落实。

## 验收场景

- 用三个真实项目和五条真实笔记走通创建、更新任务、关联知识、搜索的流程。
- 看板拖动后，表格及项目详情呈现同一状态，重启后仍保留。
- 四端各自断网编辑，再联网同步，其他端能够获得相同记录与关系。
- 两台设备离线修改同一笔记时，两份内容都能找回，并可完成合并。
- 上传附件中断后可重试，界面准确说明附件是否可用。
- 从完整备份恢复到新的空工作区，项目、任务、笔记、关系和附件保持一致。
